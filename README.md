# Agency Android — GitHub Build Package

هذه الحزمة مبنية على الملف المرجعي `README (3).md` المقدم في المحادثة.

## ما تم تضمينه

- `REFERENCE_README.md`: نسخة كاملة من الملف المرجعي كما ورد، دون حذف أو اختصار أو إعادة صياغة.
- `reference-code/`: فصل جميع كتل الشيفرة الموجودة في الملف المرجعي إلى ملفات مستقلة. محتوى الكتل محفوظ كما هو؛ كتل الشيفرة التي لم يحدد المرجع لها مساراً محفوظة في `unmapped-snippets/`، وكتلة إعداد Gradle الأصلية محفوظة في `legacy-build-config/`.
- `app/`: مشروع Android قابل للبناء كنقطة تشغيل تمهيدية.
- `.github/workflows/android-build.yml`: بناء تلقائي لملف APK عند push أو pull request أو تشغيل workflow يدوياً.
- `REFERENCE_GAPS.md`: قائمة بالنواقص التي تظهر من مقارنة الاستدعاءات والملفات الواردة في المرجع.

## البناء على GitHub

1. ارفع محتويات هذا المجلد إلى مستودع GitHub جديد، مع الإبقاء على أسماء المجلدات والملفات.
2. افتح تبويب **Actions** في المستودع.
3. شغّل **Android Build** يدوياً من `Run workflow`، أو ادفع commit جديداً.
4. بعد نجاح التنفيذ، افتح تفاصيل الـ workflow ثم نزّل artifact باسم `agency-debug-apk`. يحتوي على `app-debug.apk`.

## البناء محلياً

المشروع يستخدم JDK 17 وGradle 8.4 وAndroid SDK Platform 34. بعد تثبيت الأدوات وإعداد `ANDROID_HOME` نفّذ:

```bash
gradle --no-daemon :app:assembleDebug
```

الناتج:

```text
app/build/outputs/apk/debug/app-debug.apk
```

## تنبيه نطاق البناء

الـ APK الناتج حالياً هو APK تمهيدي يثبت سلامة هيكل مشروع Android وخط البناء. لم يتم وضع ملفات الشاشات المرجعية غير المكتملة داخل source set النشط؛ لأن الملف المرجعي يستدعي عدة ViewModels ومكوّنات وخدمات لا يحتوي على تطبيقاتها. إدخالها مباشرة سيجعل البناء يفشل أو يتطلب اختراع سلوك غير موجود في المصدر. لذلك حُفظت كاملةً ومن دون تعديل في `reference-code/`، مع الإبقاء على النص الأصلي كاملاً في `REFERENCE_README.md`.

لا يعني نجاح بناء الـ APK التمهيدي أن جميع وظائف المدير والمخزن والمشتري والمتحصل والمحاسب أصبحت مطبّقة. راجع `REFERENCE_GAPS.md` قبل اعتبار المنتج جاهزاً للتشغيل التشغيلي.
